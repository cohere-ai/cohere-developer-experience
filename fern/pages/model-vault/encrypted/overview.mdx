An **Encrypted Vault** is a vault with confidential-computing protections layered on top of the
standard deployment. Your prompts, responses, and model weights stay protected end to end inside
hardware-backed trusted execution environments (TEEs), and you can cryptographically verify what is
running before you send any data.

Encrypted vaults deploy and run exactly like any other vault — you use the same
[shared vault flow](/docs/model-vault/quickstart) — so this section covers only what's **specific** to
encrypted vaults: the security model, verification, key management, compliance, and the models and
pricing that apply.

## What Encrypted Vaults add

- Data is protected **in transit, at rest, and in use** — even from the infrastructure operator.
- Verifiable **remote attestation** lets you confirm the genuine TEE and the exact code running before each connection. (This is what the vault's verification badge in the dashboard reflects.)
- Designed to help regulated organizations meet compliance obligations (for example, GDPR, HIPAA, SOC 2).

<Note>
Don't need confidential-computing protections? A [Standard Vault](/docs/model-vault/standard) offers
the same managed, single-tenant deployment without the encryption-in-use and attestation features.
</Note>

## Deploy an Encrypted Vault

Follow the shared flow, choosing the **Encrypted** option when you create the vault:

<Steps>
### Understand what Encrypted Vaults protect

Review the [Security Model](/docs/model-vault/encrypted/security-model) to understand the trust
boundary and threat model — specifically who is (and is not) able to access your data and model
weights.

### Learn the foundations (optional)

New to confidential computing? Read the
[Confidential Computing Primer](/docs/model-vault/encrypted/confidential-computing) for a quick
grounding in TEEs, secure enclaves, and GPU confidential computing.

### Create your vault

Provision a vault as usual and enable the encrypted option — see
[Creating a Vault](/docs/model-vault/creating-a-vault).

### Verify your deployment

Before sending sensitive data, confirm the environment is genuine and running the expected code via
[Remote Attestation](/docs/model-vault/encrypted/attestation) and
[Verifying Your Deployment](/docs/model-vault/encrypted/verifying-deployment).

### Configure encryption and keys

Review [Encryption & Key Management](/docs/model-vault/encrypted/encryption-key-management) to
understand how data is protected in transit, at rest, and in use, and how keys (and ZDR) are handled.

### Call your vault

Make inference requests using your vault endpoint — see
[Calling a Vault over the API](/docs/model-vault/api-access). The client verifies attestation before
each connection.

### Confirm compliance

Check [Compliance](/docs/model-vault/encrypted/compliance) for how Encrypted Vaults map to GDPR,
HIPAA, SOC 2, and audit-logging requirements.
</Steps>
